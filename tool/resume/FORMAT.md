# Resume build contract

`resume:build` reads the canonical schema-11 portfolio record and emits a standalone semantic HTML document and a tagged PDF. The CLI accepts `--out` and `--paper a4|letter`; A4 is the default. No runtime service or network access is used.

All experience entries retain source order, including education already recorded as experience. Company, role, period and summary are printed without inferred dates or facts. A separate education section is not inferred from IDs or free text. Empty optional sections are omitted. Contributions use at most three entries, packages three, and writing two: authored featured entries in source order, or the first entries in source order when none are featured. URLs remain visible and must be absolute HTTPS URLs. The profile email is plain text.

The build embeds the repository's Latin Inter subset from `assets/fonts/inter/Inter-Variable.ttf`, covered by the adjacent OFL license. The pure HTML renderer can also use system fallbacks when no font bytes are supplied. Print CSS supports both paper sizes. The CI browser check requires the current canonical record to fit one or two pages and checks page dimensions, accessibility tags and the heading outline. Longer clone records are not truncated; they can produce additional pages.

Chromium writes wall-clock `/CreationDate` and `/ModDate` in its document information dictionary. A trailer `/ID`, when emitted, can also vary. Normalization replaces the entire information dictionary with title, profile-name author, profile-role subject, focus keywords and UTC midnight dates from `verified_at`. It rebuilds byte offsets in the classic cross-reference table and writes a content-derived SHA-256 document ID (first 128 bits). Compressed content, embedded fonts, links, page resources and accessibility tags are preserved. No timestamp or producer version is added.

The parser intentionally accepts only the generated Chromium format: one unencrypted classic cross-reference table, generation-zero objects, direct stream lengths, and unfiltered or FlateDecode streams. Text verification follows page content streams and their font ToUnicode maps, supporting hexadecimal Tj/TJ text with bfchar and bfrange mappings. Metadata-only names fail. Object streams, incremental updates and XMP metadata fail explicitly rather than silently bypassing normalization.

Byte determinism is checked across separate Chromium launches, more than a second apart, for both paper sizes in CI. The A4 result must equal the actual release PDF. Bundle verification requires idempotent normalization and every experience company, role, period and summary in the PDF text layer. Determinism applies to identical content, font bytes, tooling and rendering environment; it is not a promise across operating systems or browser upgrades. Local unit tests do not launch a browser.

Release integration uses the maintainer build command and the CI build job, before bundle verification and packaging. Hosted Vercel/Netlify builders currently require a coordinator change to install/cache Chromium: their existing browser-free build contract cannot satisfy PDF generation. The coordinator must also add PDF revalidation/MIME policy to the hosting configurations before deployment.
